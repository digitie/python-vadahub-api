# 적대적 리뷰 2명·live E2E·머지 gate

사용자가 요구한 필수 절차이며 문서 PR과 모든 구현 PR에 적용한다.

## 독립 리뷰

작성 agent와 별도의 context를 가진 리뷰어 A/B 두 명을 실행한다. 같은 작성자의
시점 전환이나 동일 결과를 두 번 기록하는 것으로 대체하지 않는다.
리뷰어는 코드를 직접 수정하지 않고 파일/행·재현 근거·사용자 영향·우선순위를 보고한다.

| 리뷰어 | 공격 관점 |
|---|---|
| A | 원천 계약·익명 DBF/TXT·GDAL/CRS·전체/구간·선착장 오매핑·완전성·문서와 실제 차이 |
| B | async 종료·취소·소유권·세션 경쟁·할당량·ZIP/경로·원자 저장·native ABI·검증 허위성 |

검토 입력은 PR base/head SHA, diff, 사양, 검증 결과다. 각 리뷰는 P0/P1/P2 지적과
차단 여부를 명시한다. 지적마다 수정 SHA·재현 테스트·재리뷰 결론을 기록한다.
P3는 이유 있는 후속 task로 남길 수 있으나 데이터 손실/오매핑 위험을 P3로 낮추지 않는다.
두 리뷰의 검증 완료 전에는 ready/merge하지 않는다.

## live E2E

실제 공개 VadaHub를 Chromium으로 사용하며 API 키·로그인 없이 실행한다.
문서 PR은 실제 catalog→4 meta→7 layer→공개 버튼 ZIP 6개·터미널 미제공 상태와
로컬 GDAL 읽기를 증빙한다. 구현 PR은 해당 공개 라이브러리 메서드로 같은 흐름을 검증한다.
fixture/mock·기존 ZIP만으로 다운로드 live를 대체하지 않는다.
원천 레코드 수는 snapshot 기준이며 갱신 시 새 수량/변경 원인을 기록한다.
401/403/429·로그인/CAPTCHA는 실패다. 우회하지 않고 해당 gate를 미통과로 둔다.

기록: KST 시각, 실행 명령·환경(Python/Chromium/GDAL), 소스 SHA, 대상 URL,
성공/실패/skip 수, 실제 bytes/hash/행수/가용상태, 알려진 한계, 리뷰어별 최종 결론.
쿠키·브라우저 프로필·원문 HTML 전체·비밀값·대용량 ZIP은 커밋하지 않는다.

## SHA와 머지

최종 구현 SHA가 바뀌면 영향받는 테스트/live와 두 리뷰를 다시 확인한다.
검증 기록만 추가한 후에는 구현 파일 diff가 없는지 확인하고 최종 head CI도 기다린다.
review를 GitHub 계정의 APPROVE로 위조하지 않는다. agent 리뷰 증빙으로 기록한다.
원격 CI의 모든 필수 job 통과·리뷰 차단 없음·live 성공을 확인하고 expected head SHA를
지정해 squash merge한다. merge 성공과 원격 main SHA를 확인한 뒤 다음 task를 시작한다.

외부 장애로 검증이 불가능하면 PR을 열어 두고 실패 이유·재현 명령·다음 작업을 기록한다.
단순 skip을 성공이라고 보고하거나 gate를 임의 면제하지 않는다.
