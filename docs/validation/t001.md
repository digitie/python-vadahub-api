상태: live·GDAL·독립 재리뷰 2건·문서 CI 통과, 머지 대기.
검증한 최종 도구 코드 SHA: `bb2c7f1ac25733c366e5f9cbca545d90e0a2b80f`.

## 실제 조사

2026-10-24 KST, Windows Python 3.14, Playwright async Chromium 149 실행.
최신 Playwright 기본 Chromium 다운로드는 CDN timeout으로 실패했다.
이미 설치된 Chromium 실행 경로를 명시해 실제 공개 UI 다운로드에 성공했다.
API 키·로그인 없이 공간 카탈로그 183 meta, 대상 4 meta와 7 layer를 확인했다.
도선항로·여객항로·관광지정보 4개 layer 총 6 ZIP을 공개 버튼으로 내려받고 CRC 및 전 행을
사전 pyshp 검사했다. 34/424/38/142/109/110건이다.
최종 재현은 2026-10-24 **11:49:56 KST**에 Chromium 149.0.7827.55로 시작했고
[공개 receipt](t001-public-receipt.json)에 코드 SHA·시각·카탈로그·6 ZIP hash·member hash를 기록했다.
source-analysis의 최초 수집 hash와 최종 수집 hash는 다르다. 서버가 ZIP을 매번 재생성하며
재수집한 ZIP 전 멤버 payload 바이트는 같고 timestamp가 바뀜을 확인했다.
원문 ZIP의 식별과 데이터 내용의 변경을 구분한다.
여객터미널은 `dwldPosblYn=N`이고 다운로드 버튼이 없다. 원격 SHP 성공 항목이 아니다.
관광지 4번째 자료는 전체보기 버튼으로 펼친 뒤 다운로드했다.

## GDAL

사용자 추가 지시에 따라 kor-travel-geo의 ADR-005/loader를 확인했고,
WSL Ubuntu-26.04 Python의 GDAL 3.12.2로 실제 ZIP 6개 읽기를 성공했다.
GDAL feature count 및 **실제 feature 반복 수**는 34/424/38/142/109/110으로 일치하고 각 SRS는
None이었다. [GDAL receipt](t001-gdal-receipt.json)에 전체 필드 매핑·수량·CRS를 기록했다.
각 feature의 TXT/DBF field 집합 일치와 geometry 존재도 확인했다.

실행 명령(기존에 설치된 Chromium을 명시):

```text
python tools/probe_source.py --output-dir artifacts/t001-final --download --executable-path <설치된 Chromium 경로>
python3 tools/probe_gdal.py artifacts/t001-final
python tools/check_docs.py
python -m compileall -q tools
git diff --check
```

## 독립 리뷰 1차와 수정

- A(`review_a`): P2 1건, 최초/최종 hash 증빙 혼동. 실행별 receipt와 source SHA를 추가하고
  ZIP timestamp-only 변화를 명시했다.
- B(`review_b`): P2 2건, 재실행 중간 실패의 이전 성공 훼손 및 CRC 전 ZIP 제한 누락.
  새 output 디렉터리를 강제하고 공통 ZIP preflight로 크기·비율·멤버·경로·중복을 검사한다.
- 합성 ZIP으로 압축비 과다·33멤버·상위경로·대소문자 중복을 검사했다. `testzip`에 실패 mock을
  걸어 해제 전에 거부함을 확인했다. 기존 디렉터리 재실행도 네트워크 전에 거부하고
  이전 report/원문을 보존함을 확인했다.
- 수정 후 실제 공개 ZIP 6개 다운로드와 GDAL 전 행 검사 모두 재통과했다.
