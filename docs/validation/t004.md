# T004 GDAL loader 검증

상태: 독립 리뷰2·live5·필수 GDAL 포함 CI 통과. 증빙 head CI 확인 후 머지.
T003 머지 `d342204`에서 분기했다.

GDAL native 객체는 worker 내부에서만 사용한다. 검증된 로컬 ZIP을 ESRI Shapefile
driver로 열고, cN 필드와 CP949 TXT의 원본 columnName을 정확히 연결한다.
미확인 CRS를 추정하지 않으며 `.prj` 또는 호출자의 명시적 근거만 변환한다.
reader는 2 batch queue, batch당 4MiB 목표, feature WKB 16MiB 상한을 둔다.
단일 feature는 batch 목표보다 클 수 있다. 취소/early-close는 worker 해제까지 기다린다.

Windows Chromium과 WSL Ubuntu-26.04 GDAL 3.12.2의 분리된 live를 실행한다.
최종 구현 SHA `e3abca4c60825ca0609645589b854e882def3df1`.
offline **151 passed/93.79%**, mypy11files·compileall·diff 검사 통과.
동일 SHA에서 Windows의 실제 Chromium live4와 새 ZIP 6개의 WSL GDAL live1 모두 통과했다.
각 환경은 대상 테스트 파일을 명시하여 **skip0**을 확인했다.
GDAL 전 행은 34/424/38/142/109/110이며 모두 CRS 미상이다.
[원문 및 GDAL receipt](t004-live-receipt.json)에 ZIP·멤버·파싱 해시를 연결했다.

A의 P2(WGS84 위도95 통과)는 finite/envelope 검사와 실제 GDAL 회귀로 수정했다.
B의 P2(native wrapper가 예외 traceback으로 thread 경계 통과)는 worker 안에서
traceback/cause/context를 해제하고 dataset보다 자식 wrapper를 먼저 해제해 수정했다.
A는 수정 SHA에서 독립3개 테스트, B는 실제 중복ID traceback 재현과 공간19개 테스트로
해소를 확인했으며 두 리뷰어 모두 남은 P0/P1/P2가 없다고 확인했다.

[구현 SHA CI](https://github.com/digitie/python-vadahub-api/actions/runs/40059699029)는
core 3.11~3.14·typecheck·필수 spatial 모두 통과했다. docs도 통과했다.
증빙 문서만 추가한 최종 head의 CI를 다시 확인하고 머지한다.
